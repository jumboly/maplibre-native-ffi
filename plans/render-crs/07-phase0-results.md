## パイプラインの検証（自動確認済み）

- **zoom の一致**: equivalentZoom の Python 移植が GL JS 版と同値を返す （都庁
  1:5000 → z15.5524、都庁 1:25000 → z13.2304、根室 1:5000 → z15.3933）
- **出力寸法の semantics**: HeadlessFrontend は `floor(論理px × ratio)` で確定。
  3 ケースとも期待どおり（5100×3625 / 1850×1350 / 1223×894）で、GL JS 版の
  キャンバス量子化補正は不要と実証
- **ワープ先グリッドの厳密一致**: gdalinfo の origin / pixel size が
  `center ± mpp·px/2` / `scale·0.0254/dpi` の導出値と全桁一致
  - 都庁 1:5000: origin (-13869.067, -33696.450467), 0.423333… m/px, EPSG:6677
  - 根室 1:5000: origin (107519.761292, -73042.617983), 1.322917… m/px,
    EPSG:6681
- **絵の妥当性**: 都庁スモーク（512×512）と根室 warp を目視確認。ラベル・道路・
  建物が正しく描画される

## 案 C の品質所見

比較クロップは `phase0/crop_compare.py` が生成する（3 領域 × 4 画像、4 倍拡大、
`build/render-crs-phase0/crops/`）。フェーズ 3
の受け入れ時は、フック方式の出力に 同じ窓を適用して並置する。

- **都庁 IX 系（γ≈0.08°、300dpi）**: 劣化は軽微。中心部はワープ変位が
  サブピクセルのため元画像とほぼ判別不能で、画像端（回転変位 ≈3.5px）でも
  細線がわずかに柔らかくなる程度
- **根室 XIII 系（γ≈0.92°、96dpi）**: 全面で実質的な回転リサンプリングが入り、
  劣化が明確。「根室駅」のラベル文字とハローの輪郭が滲み、細い道路線・鉄道線は
  グレーが広がって太さが不均一になる。bilinear が最も柔らかく、cubic は中間、
  lanczos がエッジ保持で最良だが、それでも元のシャープさには届かない
- **原理的な限界（リサンプラ非依存）**: ラスタごと回すため、viewport-align の
  ラベルが座標北に対して γ だけ傾いたままになる（根室で約 0.92°）。ラベルの
  直立はフック方式（案 E）でしか実現できない
- **まとめ**: 高 dpi・小 γ（都心）では案 C は実用に近いが、系の端・低解像度では
  文字と細線の滲みが明確で、「ベクタ級品質が絶対要件なら不成立」という GL JS
  版の 結論（03-approaches.md 案 C）を Native でも追認した

### フェーズ 3（フック方式 PoC）の受け入れ基準への反映

1. フック方式の出力は、同一窓の並置比較で **Mercator レンダと同等のエッジ
   シャープネス**を持つこと（warp 版で観測した再サンプリング滲みが無いこと）
2. viewport-align のラベルが**出力画像上で直立**すること（warp 版は γ だけ傾く）
3. 幾何は warp 版と同一グリッドで重畳し、道路中心線が一致すること（warp 版が
   幾何の正解参照になる）
